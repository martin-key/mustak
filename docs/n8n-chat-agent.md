# Чат асистент в n8n

Чат балонче долу вдясно на сайта, зад което стои AI агент в [n8n](https://n8n.io). Агентът отговаря за цени и бръснари, търси свободни часове и записва час. Ползва API-то за AI агента (`/api/v1`), така че правилата са същите като при записване от сайта: двойното записване е невъзможно, важат лимитите и правилата от `src/config/business.ts`.

## Как е свързано

```
Браузър                    Нашият сървър (Next.js)                 n8n
───────                    ───────────────────────                 ───
чат балонче  ──POST──▶  /api/public/chat                ──POST──▶  Chat Trigger (Basic Auth)
(React)                 • само от нашия сайт (Origin)                │
                        • лимит на IP и общ лимит                    ▼
                        • валидира съобщението               AI Agent + памет + модел
                        • добавя Basic Auth                          │ 4 инструмента
                                                                     ▼
                        /api/v1/services, barbers,     ◀──X-API-Key──┘
                        availability, bookings
```

- Браузърът говори само с нашия сървър. Адресът на n8n и паролата не стигат до браузъра, а CSP остава `connect-src 'self'`.
- Балончето е малък React компонент на сайта, без външни скриптове. Говори същия протокол като официалния widget на n8n (`action: "sendMessage"`, `sessionId`, `chatInput` → `{ "output": "..." }`), така че Chat Trigger-ът не знае разликата. Разговорът се пази в `sessionStorage`: остава при презареждане и изчезва при затваряне на таба.
- Отговорите на модела са markdown (удебелено, списъци, линкове). Рисуват се от `src/lib/chat-markdown.ts` като React елементи, никога като HTML, а линковете са само `http(s)://` или към сайта.
- n8n вика API-то на сайта със същия `AGENT_API_KEY`. Агентът има само 4 инструмента и не може да чете чужди записвания, да отказва или да мести часове.

## Какво има в workflow-а

Файлът е [`n8n/mustak-chat-agent.json`](../n8n/mustak-chat-agent.json). Генерира се от [`scripts/n8n-workflow.ts`](../scripts/n8n-workflow.ts), който взима името, адреса, телефона, работното време и правилата за записване от `src/config/business.ts`.

| Възел | Какво прави |
| --- | --- |
| **Чат съобщение** (Chat Trigger) | Публичен webhook в режим „Embedded chat“ с Basic Auth. Отговаря, когато агентът свърши (`lastNode`). |
| **Асистент** (AI Agent) | Системните инструкции на български: как се записва, кога се иска потвърждение, какво не прави. Вътре е текущата дата и час в София. |
| **Claude** (Anthropic Chat Model) | Модел `claude-sonnet-5-5`, температура 0.3. Може да се смени с друг модел (OpenAI, Gemini и т.н.). |
| **Памет на разговора** (Simple Memory) | Последните 20 съобщения на разговора, по `sessionId` от widget-а. |
| `list_services` | `GET /api/v1/services` |
| `list_barbers` | `GET /api/v1/barbers` |
| `check_availability` | `GET /api/v1/availability?serviceId&date&barberId` |
| `create_booking` | `POST /api/v1/bookings`. Стойностите идват от модела чрез `$fromAI()`. Хедърът `Idempotency-Key` е от разговора (`sessionId`), услугата, началния час и телефона: ако n8n повтори заявката или моделът извика инструмента два пъти, API-то връща вече записания час, вместо да запише клиента втори път при друг бръснар. `sessionId` е в ключа, за да не може посетител в друг разговор да състави същия ключ от чужд телефон и час. При ръчна проба на инструмента („Execute step“) на мястото на `sessionId` е `manual`. |

Инструментите връщат грешките от API-то (напр. `SLOT_UNAVAILABLE`) като текст към модела, вместо да спират workflow-а. Така агентът обяснява на клиента и предлага друг час.

## Пускане стъпка по стъпка

### 1. Генерирайте workflow-а с адреса на сайта

```bash
npm run n8n:workflow -- https://mustak.example
```

Адресът е този, на който n8n стига до сайта. Ако n8n е в Docker на същата машина, на която върви `npm run dev`, адресът е `http://host.docker.internal:3000`. Файлът в repo-то е генериран с `https://mustak.example`: или го генерирайте наново, или сменете адреса в 4-те HTTP възела след импорта.

### 2. Импортирайте го в n8n

В n8n: **Create workflow → ⋯ → Import from File** и изберете `n8n/mustak-chat-agent.json`. Или от командния ред на n8n:

```bash
n8n import:workflow --input=mustak-chat-agent.json
```

### 3. Създайте 3 credentials в n8n

| Credential | Тип | Какво попълвате |
| --- | --- | --- |
| **Мустак API ключ** | Header Auth | Name: `X-API-Key`, Value: стойността на `AGENT_API_KEY` от `.env` на сайта |
| **Мустак чат (Basic Auth)** | Basic Auth | Потребител и парола по ваш избор (напр. `openssl rand -hex 24`). Същите отиват в `.env` на сайта. |
| **Anthropic** | Anthropic | API ключ от console.anthropic.com |

Изберете ги във възлите: API ключа в 4-те инструмента, Basic Auth в „Чат съобщение“, Anthropic в „Claude“.

### 4. Публикувайте workflow-а и копирайте адреса

Натиснете **Publish**. Отворете „Чат съобщение“ и копирайте **Production URL**. Той изглежда така: `https://n8n.example.com/webhook/<id>/chat`.

### 5. Включете балончето на сайта

В `.env` на сайта:

```bash
N8N_CHAT_WEBHOOK_URL=https://n8n.example.com/webhook/<id>/chat
N8N_CHAT_USERNAME=<потребителят от Basic Auth>
N8N_CHAT_PASSWORD=<паролата от Basic Auth>
```

Рестартирайте приложението (`docker compose up -d`). Без `N8N_CHAT_WEBHOOK_URL` балончето не се показва.

### 6. Проверете

```bash
# Директно към n8n (трябва да върне {"output": "..."}):
curl -u "$N8N_CHAT_USERNAME:$N8N_CHAT_PASSWORD" -X POST "$N8N_CHAT_WEBHOOK_URL" \
  -H 'Content-Type: application/json' \
  -d '{"action":"sendMessage","sessionId":"test-1234","chatInput":"Какви услуги имате?"}'

# През сайта:
curl -X POST http://localhost:3000/api/public/chat \
  -H 'Content-Type: application/json' \
  -d '{"action":"sendMessage","sessionId":"test-1234","chatInput":"Какви услуги имате?"}'
```

После отворете сайта, натиснете балончето и запишете час. Часът трябва да се появи в админ панела с източник „AI агент“.

## Локален тест с n8n в Docker

```bash
docker run -d --name n8n -p 127.0.0.1:5678:5678 \
  -e GENERIC_TIMEZONE=Europe/Sofia -e TZ=Europe/Sofia \
  -v n8n_data:/home/node/.n8n n8nio/n8n:2.45.3
npm run n8n:workflow -- http://host.docker.internal:3000 /tmp/mustak-chat-agent.json
```

Отворете http://localhost:5678, импортирайте файла и продължете от стъпка 3. В `.env` на сайта адресът е `http://localhost:5678/webhook/<id>/chat`, защото сайтът вика n8n от хоста.

Всеки инструмент може да се пробва и без модел: отворете възела и натиснете **Execute step**. n8n пита за стойностите, които иначе дава моделът.

## Сигурност и поверителност

- **Чатът не минава през Turnstile.** Пазят го: лимит от 30 съобщения за 10 минути на IP и 600 на час общо (`RATE_LIMITS.chatPerIp` и `chatGlobal`; общият брои само валидни съобщения в лимита на IP, така че един клиент не може да изчерпа чата за всички), проверка на `Origin`, лимитите на API ключа (10 записвания в минута) и правилото за най-много 3 бъдещи часа на телефон. Агентът записва само след изрично „да“ от клиента.
- **Всяко съобщение струва заявка към модела.** Затова е общият лимит. Сложете и месечен лимит на разходите в конзолата на доставчика на модела.
- **Данните на клиента отиват към n8n и към доставчика на модела** (име, телефон и текстът на разговора). Това е второто изключение от правилото „без външни услуги“, по решение на собственика. Споменете го в политиката за поверителност. Ако n8n е на ваш сървър и моделът е локален (напр. през Ollama), данните не напускат вашата инфраструктура.
- **Prompt injection.** Клиентът може да пише каквото си иска на агента. Затова агентът има само 4 инструмента, които и сайтът позволява на всеки посетител. Не му давайте инструменти, които четат или променят чужди данни. Внимавайте и с ключове, които моделът може да състави: първата версия на `Idempotency-Key` беше само от услуга, час и телефон и посетител, който знае чужд телефон, можеше да получи чуждото записване с името и имейла (вижте [how-we-built-it.md](how-we-built-it.md), „На какво се натъкнахме“).
- **Паметта** (Simple Memory) е в паметта на процеса на n8n и се губи при рестарт. Ако n8n работи в queue mode или с няколко инстанции, сменете я с Postgres Chat Memory.
- **Chat Trigger-ът е с Basic Auth.** Без него всеки, който знае адреса, може да пише директно на агента и да харчи от модела.

## Промени

- **Друг модел:** изтрийте „Claude“, добавете друг Chat Model възел и го свържете към „Асистент“.
- **Друго име, адрес или правила:** сменете `src/config/business.ts` и генерирайте workflow-а наново.
- **Текстовете и видът на балончето** (заглавие, поздрав, цветове) са в `src/components/site/chat-bubble.tsx`.
- **Официалният widget на n8n** (`@n8n/chat`) също работи с този workflow, но не го ползваме: дърпа Vue и голяма част от пакетите на n8n, а `npm audit` показва 16 уязвимости (12 high) в тях. Нашият компонент е около 250 реда и няма зависимости.
